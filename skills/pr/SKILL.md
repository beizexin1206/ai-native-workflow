# /pr —— 提交代码审查请求

## 前置

核对需求、批准方案、实际分支和目标基线、项目验证与审查要求。需要的检查未执行时先执行；不可执行的报告限制，不把历史结果当当前结果。

工作区改动按归属处理，不要求为了开审查清空所有修改。分支名、工作项编号、提交和同步方式沿项目约定；不自动 rebase、强推或重命名分支。

## 描述

优先采用项目已有模板。没有模板时可参考本包 `templates/merge-request.md`，按规模说明：

- **What**：原问题与新行为，需求有实际链接时引用。
- **Why**：来自已批准方案或实际决策记录，不能从 diff 编造；真实重要理由缺失时说明缺口。
- **How / Scope**：实施路径、影响面及必须保护的能力。
- **Tests**：实际运行的验证、结果和未覆盖限制。
- **注意点**：适用的迁移、兼容、回退、风险和审查重点。

不要求固定出处目录、六段标题、任务编号或占位空表。已有方案和对话依据可以直接使用。

## 创建或更新

使用项目实际代码平台及已有 CLI/连接器，核对同分支是否已有请求，存在则更新，不重复创建。按用户授权提交或推送本任务代码；通过结构化参数或正文文件传递描述。

是否草稿、目标分支、审查者、合并方式和源分支清理由项目决定。创建请求不包含合并或发布授权。

项目要求任务关联且授权允许时回写实际链接；没有任务系统不构成阻塞。报告审查链接、标题、当前检查结果和未完成部分，未执行的动作不计完成。
