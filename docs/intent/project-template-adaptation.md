# 项目模板适配

## 背景

部分团队需要在迁移期继续使用既有 PRD、技术设计、测试和交付文档，但把这些模板直接加入公共默认流程，
会迫使所有项目维护并不需要的产物，并形成重复事实源。

## 决策

公共主线和默认产物保持不变。项目若在 `docs/templates/` 下自带子目录，即表示主动选择额外评审制品；
`/pd`、`/p`、`/t` 在对应阶段自动读取相关模板，从主流程已有事实生成派生视图。项目无需安装额外 Skill、
记忆新命令或维护 Profile 配置，没有项目模板子目录时行为与精简流程完全一致。

派生视图不替代 Meegle、SPEC、代码、测试、CI、缺陷系统和 `docs/intent/`，也不新增公共审批门禁。
删除项目模板子目录即可退出兼容模式。

## 取舍

- 未选择独立兼容仓库的运行时 Skill：需要第二次安装和额外编排，增加使用复杂度。
- 未把模板重新放回公共 `/init`：模板是项目习惯，不是所有用户的默认约定。
- 未要求人显式触发：项目模板目录已经表达选择，Agent 可在阶段内自行判断并生成。
