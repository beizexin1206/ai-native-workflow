# `/start`：面向普通用户的总入口

## 问题

现有能力覆盖了从产品需求到 MR 的完整链路，但普通用户必须理解各阶段并依次选择 `/pd`、`/bl`、
`/s`、`/p`、`/b`、`/t`、`/rv` 和 `/mr`。这把流程编排责任留给了用户，也让中断恢复和阶段跳转
依赖用户记忆，不符合 AI Native 的使用方式。

## 方案选择

- 候选 A：继续用操作手册解释全部命令。实现成本最低，但用户仍然是流程驾驶员。
- 候选 B：提供一段提示词，让用户自行要求 Agent 依次运行命令。入口更短，但没有稳定的阶段识别、
  恢复规则和停止边界。
- 选择 C：增加 `/start` 总入口，由 Agent 恢复现场并调度现有能力，只在业务决定、方案决定、风险权限
  和对外交付时停下来。

选择 C，因为它把流程编排交给 Agent，同时复用已有 skill 的事实来源、产物和质量门禁。底层能力仍可
独立调用，便于专业用户处理单一阶段，也便于定位和改进具体流程。

## 边界

- `/start` 不替用户决定需求、范围、优先级或重要技术取舍。
- `/start` 不绕过现有 skill 的前置条件、测试和 review。
- `/start` 不合并 MR，不部署或发布，也不扩大外部操作权限。
- 本次只增加总入口和公开说明，不修改现有 13 个 skill 的独立行为。

## 发行影响

安装包从 13 个 skill 增加到 14 个；`install.sh` 已按目录动态发现 skill，无需修改。README 和注入项目的
`AGENTS.block.md` 同步增加 `/start` 入口。面向具体客户的操作手册不属于公共发行包，本次不提交。
