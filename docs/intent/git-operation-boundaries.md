# Git 操作边界：冲突时暂停，分支基线由人决定

## 背景与决定

团队反馈：需求分支向集成分支提 MR 时，Agent 为处理冲突自行 rebase 到集成分支，
导致需求分支混入其他需求的历史。此次先补行为约束：未经明确授权，不改写历史、不强推，
不把 MR 目标分支当作需求开发基线；遇到冲突暂停并报告，交由人决定。

这是一项基于团队反馈的防护措施，不代表已独立复核具体事故的全部 Git 历史。

## 取舍

- 只禁止 `rebase beta` 不够：`pull --rebase`、平台 Rebase 和将目标分支 merge 回需求分支
  也可能越过同一边界，因此共同约束，并覆盖 `--force-with-lease`。
- 暂不调整团队分支模型、GitLab 合并设置或增加命令拦截；先以最小规则补丁降低误操作风险。
- 原共享约定、`/b`、`/mr` 要求自动 rebase，与新规则冲突，必须同时替换为获取远端状态、
  核对基线关系以及需要同步时报告方案。`/fb` 明确区分修复评审意见与 Git 操作的授权。
- 此处保留用户针对具体操作的明确授权，不把规则解释为永久禁止所有 rebase。

## 生效与限制

规则随 Skill 更新分发。已有消费项目还需重新执行 `/init`，更新 `AGENTS.md` 的标记块；
`/init` 已支持替换该块，无需改变其实现。项目自有分支约定需与新规则一并核对。

这是行为约束，不是技术上的命令拦截。此次不包含客户材料、测试文档改造或 GitLab 权限配置。
本仓库 Fork 的 PR 合入后，仅更新该 Fork 的用户能获得补丁；仍使用原上游安装源的用户，
需要等待补丁进入上游或明确切换安装源，重新 `/init` 不能代替更新安装源。
