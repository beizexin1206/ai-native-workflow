# 过程产物的生命周期判断

## 背景

Agent 在执行工作流时会产生文档、脚本、日志和其他中间产物。仅按文件类型或“是否本轮生成”判断留存，
容易把仍承载独有知识、能力或证据的产物误删；反过来枚举所有应保留的产物，又会让规则随案例膨胀，
无法覆盖新的工具和载体。

## 决策

产物是否可清理，统一按其价值是否已被更稳定的事实源完整接管判断。删除后如果不能同等程度地理解、
复现和维护，就先迁移、重构或纳入正式资产；只有完成接管后，原产物才属于可清理的脚手架。

各阶段 Skill 负责说明最终要沉淀的能力，项目上下文负责指出稳定事实源的位置，Agent 据此判断具体产物，
不在共享规则中按文件后缀、工具或案例穷举。

## 影响

仓库整洁仍然重要，但不能以丢失可复现性为代价。发生冲突时，先保存价值，再通过归档、重构或迁移降低噪声。
