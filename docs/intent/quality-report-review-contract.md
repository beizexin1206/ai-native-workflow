# 质量报告公共契约的取舍

## 候选方案

1. 复刻测试团队原有的完整报告，把用例、缺陷、证据和 Agent 执行过程全部放进 HTML。
2. 维持当前极简报告，只保留总数、缺陷和上线建议。
3. 保持 `test-cases.md` 与 `quality-report.html` 分工，在 HTML 中补回影响人工决策的摘要和例外信息，详细事实通过稳定链接追溯。

## 选择

采用方案 3。

## 理由

- 公共模板服务多个团队，不应绑定某个项目或某种 Agent 编排。
- 人工 Review 需要的是决策密度和证据可追溯性，不是重复阅读完整用例与日志。
- 过度压缩会隐藏优先级、证据降级、人工裁决和发布依赖，降低上线判断质量。
- 用例设计、缺陷状态和原始证据各有唯一事实源，报告只保存本轮快照与决策依据。

## 适用边界

- 普通改动使用公共必填区即可。
- 多仓、接口、schema 或独立部署变更启用可选联合发布评估。
- 项目特定的打回统计或角色编排可以自行扩展，但不进入公共必填契约。
