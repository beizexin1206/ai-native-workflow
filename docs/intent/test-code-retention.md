# `/t` 测试代码留存规则

## 背景

`/t` 会按验收标准生成可执行测试。此前 Skill 只明确了测试设计、质量报告和执行证据的留存，
没有直接规定生成脚本的生命周期，Agent 可能把验收套件当作一次性冒烟脚本，在执行后删除。
这会丢失回归保护，也让后续人员无法复核测试实现和重复执行结果。

## 决策

- 验收、回归和缺陷复现测试属于正式测试代码，默认进入项目既有测试目录并保留。
- 一次性环境探测、数据排查和定位脚本优先放在系统临时目录，完成后可以清理。
- 临时脚本包含独有行为或断言时，先将其迁移为可重复执行的正式测试，再清理脚本。
- `/t` 交付前检查本轮测试文件的新增、修改和删除，并说明正式测试的运行命令和去向。

## 未采用的方案

- **所有生成脚本一律保留**：会把环境探针、敏感数据处理脚本和不可重复的调试代码带入仓库。
- **执行完成后一律删除**：会删除验收和复现测试，破坏测试事实源与长期回归能力。

因此，是否留存由脚本承担的测试职责决定，不由 `.py`、`.ts` 等文件后缀决定。
